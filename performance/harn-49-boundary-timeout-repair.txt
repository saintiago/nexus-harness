HARN-49 timeout repair: the boundary layer's default deadline
=============================================================

Recorded 2026-09-22 on the Windows host used for this whole task (24 logical CPUs, Node v24.14.1,
npm 11.11.0, Vitest 5.0.0, Turborepo 2.11.2). The sections below quote the commands and the lines
that carry the claim; nothing here is a controlled benchmark, and the host was shared with other
work while it ran (the harness's own run record names more than thirty Node processes on the host).

3. The probe that shows which deadline applies
----------------------------------------------

A temporary case that sleeps 6.5 s (`tests/timeout-probe.test.ts`, removed again and not part of the
suite), run in the boundary project before and after the change:

   $ npx vitest run --project boundary tests/timeout-probe.test.ts
   Test Files  1 passed (1)
        Tests  1 passed (1)
     Duration  6.62s (tests 100%)

   $ npx vitest run --project boundary tests/timeout-probe.test.ts --testTimeout=5000
   Test Files  1 failed (1)
        Tests  1 failed (1)
     Duration  5.13s (tests 100%)
   → Test timed out in 5000ms

The same case, the same configuration file, the same command: only the deadline differs, so
`testTimeout: BOUNDARY_DEFAULT_TIMEOUT_MS` in the boundary project is what applies to a case that
states no bound of its own.
